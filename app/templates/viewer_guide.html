Publishing guide

A repeatable file handoff, with company information kept on company systems.

Back to Export to viewer

1. Prepare the weekly release

Open Prepare release. Choose company and variety coverage, select newsletter stories and tick the reports to expose internally. Review the counts, changes and asset omissions, then download the package. Previous newsletter editions remain available. Report selections are remembered for the next release.

2. Keep corporate inputs separate

Download the starter kit for first-time setup. Keep corporate settings and flavor files outside the folder that gets replaced each week. Use the company ID lookup for tier assignments.

  • Tiers: Tier 1, Tier 2, Tier 3 or Unassigned. Varieties match the tiers of their associated companies.
  • Projects: corporate HTML pages, owners, milestones and task status. Native checkboxes are temporary marks; saving shared status means updating the corporate source and publishing it.
  • Flavor: optional corporate-only records. Keep all four panels distinct and never combine their scores.

3. Give Copilot a concrete publishing task

Ask Copilot to read the package’s START-HERE.md, COPILOT-HANDOFF.md and PROJECTS-AND-TIERS.md, verify the manifest and build a fresh staging folder using the included publisher. The normal weekly update should not require redesigning or reconstructing the website.

python publisher/static_site.py --workspace content/workspace.json --corporate corporate-site.json --output new-staged-site

Add the optional corporate flavor file only on corporate systems. No Python is required to read the published HTML; it is only the offline publishing tool.

4. Publish and verify the complete folder

Preserve all relative page, asset and report-download links. Retire files absent from the new manifest so deselected reports do not linger. Retain the previous release separately for rollback. Check your actual SharePoint publishing route, inline CSS and native filter support, access controls, source links, downloads and caching. Text search uses the browser’s Find command.

After successful corporate publication, confirm the generated release in the platform. Future change reports compare against that confirmed baseline. The confirmation itself does not publish anything.

Files and limits

The full release includes the site, research JSON, selected reports, locally packaged assets, manifest, change report and publisher instructions. Workspace limit: 10 MB. Asset limits: 2 MB per file and 5 MB total. Oversized or unavailable source files are listed explicitly.
