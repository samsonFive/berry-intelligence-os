# Private Social Listening runtime transfer

Use `python scripts/social_runtime_snapshot.py <new-private-directory> --inbox <private-inbox>` to make a consistent SQLite backup, copy only referenced stored media after validating its SHA256, and preserve saved social views. Credentials, raw trial receipts, unrelated watches and canonical data are excluded. Use a gitignored private directory; this contains retained source text and is not a public static artifact. No request, upload, scheduler, deployment or import is performed.

Verify with `python scripts/social_runtime_snapshot.py <snapshot-directory>` before opening the destination as an application runtime. A hash manifest plus SQLite integrity check detects altered transfers. The destination must be new and outside the source inbox. A failed export is incomplete; do not use it unless verification succeeds. No existing runtime is overwritten. Preserve the original backup for rollback; destination writes can change SQLite hashes after it opens as a mutable runtime.

The bundle supplies `inbox/social/observations.sqlite3`, referenced `inbox/social/media/<mode>/<hash>` and an isolated `inbox/watchlist_state.json` containing social profiles with empty unrelated watches. It preserves all modes, deletion/translation/collection receipts and audit tables rather than converting fixtures into live data. Fixtures remain distinct and must be excluded by existing live views. This is a social-state component, not the entire canonical data or application deployment. Do not overwrite a server's existing watchlist state; merge social profiles through the established revision-aware saved-profile path after backup, or use a fresh staging runtime.

The existing generic demo exporter clears its destination inbox; run it first into its own fresh directory, then prepare/verify this separate component. Do not run the generic exporter over a populated social runtime.
