# Reusing source work within one request

Coverage and variety profiles validate the same saved portfolio observations
more than once during a request. The profile-field inventory also builds a
candidate/provenance result it never consumes. This follow-up shares validated
observations within the existing request corpus and lets that inventory request
source rows alone.

The next request validates current files again. CLI calls and other data
directories do not reuse the request snapshot. Failed validation is not cached
as success. Source-only reconciliation still evaluates every name, crop,
conflicting code and saved identity decision and builds the same candidate IDs.
Its default full result is unchanged. No new process cache, stored response,
serializer, capture or background job is added.

failures, another dataset, CLI edits, every saved source row, same-label/code
conflicts, wrong crops, rejected/distinct/confirmed identities, unreviewed
patent references, photo holds, hidden-photo choices and inherited navigation.

Fresh native desktop and 412px review retains the dense source table, all 21

link. Phone document and scroll widths are both 397px. Only a fictional account
is used. Record validation and the 1,797-page trusted static/Pagefind build pass; no
unpublished draft IDs or titles appear in public output.

An excluded experiment tried to reuse the entire request-owned portfolio
projection after checking every second-pass identity lookup. Its full models
and all 40 rendered responses matched, and real route reuse was exercised.
However, its fuller sequential sample regressed broad Coverage from 4.1573 to
5.9105 seconds warm median and the Hortifrut view from 3.5888 to 3.9846. That
implementation is removed from this draft. The private patch and measurements
are retained to prevent repeating the same unhelpful approach. No generic
memoization or serialization rewrite is included.

This draft adds no names, profiles, sources or market figures. Live #443 is
inherited; frozen catalog/Map #449 remains a separate release review. All 31
accepted definitions/order and the expansion guide remain unchanged, as do
schemas, CPVO, footprints, Trade/Weather and shared/private workspace boundaries.
Fresh exact-head required CI and bounded preservation/release review remain
required before any deployment. Human source, identity, role, current-rights,
photo and market-figure decisions remain separate.
