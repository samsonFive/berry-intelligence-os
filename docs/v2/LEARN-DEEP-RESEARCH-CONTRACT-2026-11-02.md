# Learn deep research — current provider contract

The full-mission audit found a real LEARN-02 gap: Learn's action labeled deep research submitted `preset=medium`. The [current official effort documentation](https://docs.perplexity.ai/docs/agent-api/effort) identifies `high` for deep, source-heavy research and `medium` for multi-hop reasoning. The [Agent request reference](https://docs.perplexity.ai/api-reference/agent-post) documents `effort`, rather than `preset`, as the selector. These public documents were checked November 2, 2026 UTC. This finding corrects the October 2 interpretation recorded in Mission 9; it does not erase that historical implementation or its actual results.

## Resulting behavior

- New Learn reservations explicitly record `effort=high`. Submission uses the saved configuration at `POST https://api.perplexity.ai/v1/agent`, with `background=true`, at most 15 steps and 6,000 output tokens. The form explains the depth, possible additional cost and latency before the explicit action.
- Company, market-reference and region research retain their existing **medium** depth and budgets. The shared transport uses the currently documented `effort` field. This repair does not authorize paid acceptance calls or change Atomic extraction qualification.
- Old jobs' original `configuration` and request fingerprints remain intact. An old, unsubmitted `preset=medium` job translates to `effort=medium`; its effective `submission_configuration` is saved before contacting the provider. It is never silently upgraded to high. Unsupported destinations, levels or budgets fail before transport.
- Old running/uncertain jobs are retrieved and cancelled by their existing provider run ID. GET, reload, repeated submission, checking, recovery and cancellation never create a replacement paid request. A submission timeout remains uncertain. Prompt text/version and topic identity are unchanged so an API field correction cannot charge an active topic again.
- The returned model, usage and provider-reported effort/version are retained when supplied. Research details distinguish the requested level from a legacy level and a reported version; historical medium results are not relabeled as high-depth research.
- Educational draft status, citations, original text, edit history, revision checks, public-output boundaries and human trust gates remain intact. No live data migration or review decision is part of this change.

## Evidence and limits

`tests/test_learn_research_effort.py` exercises the actual Learn route, production factory and adapter with only HTTP replaced: high request, saved submission settings, reported version, duplicate charging prevention, retrieval, user edits, legacy recovery/cancellation and invalid settings. Existing Learn, Company and Map research tests cover their remaining persistence, privacy and failure behavior. Tests use fixture HTTP responses, not paid provider calls. A green transport test proves the documented request shape and local lifecycle; it does not prove the quality, completeness, real cost or latency of a future provider-generated lesson.

The native browser review uses an isolated synthetic account and a clearly labeled fixture response. No real account is logged in, no original account onboarding is consumed and no provider key is needed. The original 31 requirement definitions and order remain unchanged. LEARN-02's current-provider fidelity is repaired in this draft; deployment remains a separately reviewed release.

Validated locally: **130 affected tests pass**, record validation passes, and the static build produces **1,797 pages** with its unpublished-content leakage check passing. Native desktop/412px phone review confirms one synthetic high submission, same-ID result retrieval, saved analyst edits with original/history retained, the existing interactive cane diagram, preserved return context and legacy medium cancellation. Both the form and edited lesson have equal 397px document/client widths at the phone viewport. Only the fixture transport is used; these results do not establish live provider response quality. Exact-head GitHub checks remain the merge gate.
