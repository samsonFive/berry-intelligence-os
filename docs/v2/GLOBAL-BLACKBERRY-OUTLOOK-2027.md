# Global blackberry outlook for 2027

The private leadership view at `/landscapes/global/blackberry/2027` brings the
dated global brief together with source-linked genetics, company commitments,
regional interpretation and related news. It is linked from the Blackberry
Global Berry Landscape when the research package is installed. The finished
`global-blackberry-outlook-2027` report reader links back to this view.

## Research and live information

The authored research remains in
`INBOX_DIR/blackberry_global_2027/overview.json`, outside the public repository.
Its version-one packet contains the research date, executive findings, source
register, companies, varieties, commitments, developments, regions, report ID
and limitations. The report remains a private finished-report artifact in the
existing library. Neither artifact creates canonical records or Facts.

The read model preserves commercial supply, planting, licensing, nursery
listings, rights, trials and platform commitments as separate categories.
Measures and geographic scope remain source-attributed text; rights do not
create a growing footprint. A primocane cultivar's habit is separate from its
ability to produce a crop on second-year canes. Unknown identities retain local
research drilldowns; canonical variety links require an existing Blackberry
entity of the expected type.

Region, habit, commitment, company, variety and text filters are URL state.
The shared sheet controller adds loaded-row search, sorting, column controls,
account layouts and CSV export. The view owns no duplicate canonical editor.
Regions scope the research records, while latest news follows selected genetic
identities and the linked original sources. Every article retains its own
geography and date.

News reads `main.unified_information()` in the consolidated application. The
legacy `published_evidence()` adapter is used only when the deployed baseline
has not yet gained that function; no store activation or migration is performed
by this feature. Exact stored entity IDs and exact cited URLs provide joins;
unresolved names are not inferred as canonical aliases. Explicit other-crop,
rejected, archived and future-dated items are excluded. Undated sources remain
undated and sort after dated sources; capture dates never become publication
dates. Cards, article visuals, personal actions and the shared Reader reuse the
existing News implementation. Opening the view never polls providers.

## Access and installation

The route requires authoring mode and inherits the application's existing
session authentication. It returns private/no-store responses and is absent
from static generation. Research package parsing validates format, date,
section shapes and identifier uniqueness; a missing package does not create a
fixture fallback. Original source links use the existing public URL validator.

Install the packet and finished-report assets through the release owner's
additive runtime procedure. Preserve existing report IDs, source records,
analyst state, mounted data and mounted inbox. This feature does not activate
the separately governed consolidated storage release or authorize overlapping
production deployment. Code and private runtime content are separate release
components; check the actual installed report and package after that release.

## Focused validation

Run `pytest tests/test_blackberry_global_outlook.py
tests/test_global_berry_landscape.py tests/test_report_library.py` in the
application environment. The tests cover combined scopes, canonical crop
identity, explicit unknown identities, exact source joins, source dates,
unreviewed live information, rejected/archived exclusion, private-only routes,
legacy adapter compatibility, unsafe URLs and read-only operation. Validate
the real authored package and review desktop and narrow layouts separately;
synthetic boundary tests do not establish research completeness or 2027 stock.
