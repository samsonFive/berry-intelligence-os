# Mission 24 — Honest review state in Executive View

Executive View described its mixed source, Signal and Assessment collection as trusted, even when the canonical Signal was Proposed or the Assessment was an AI draft. Its recent-updates list also omitted those states and described dates uniformly as captured/ingested. The view now leads with its briefing purpose and preserves each record's actual state beside the item. First-seen, updated, created, publication and capture dates are labeled according to the field actually used. All existing records, ranking, limits, links, original narratives and review decisions remain unchanged.

The Signal list shows the stored status, including legacy Watch or an explicit missing-state label; strength does not imply confirmation. Assessments retain the canonical schema contract: true means AI draft, while false or absent means human-authored/already-approved and retains the existing Reviewed label. The first local implementation treated a missing AI marker as unknown; schema inspection caught that backward-compatibility mistake before push, and the legacy-human regression now preserves the contract. Confidence never approves a draft. The headline and derived actor-activity captions no longer claim blanket trust or recency, and the secondary comparison with Morning Brief/Landscape is a closed disclosure. Source publications remain distinct from reviewed individual statements. This is presentation clarity, not a new trust store, status migration or publishing gate.

Static and live share this renderer and pure service. The canonical public collection remains the existing collection; pending inbox drafts/candidates and private review controls remain excluded. Public eligibility across the broader canonical corpus still needs the release audit; displaying an existing proposed record honestly is not that eligibility decision. The expansion guide and all human gates remain unchanged. Validation, browser proof and required exact-head checks are recorded below as they complete. Combined release/rollback review remains open. No merge/deployment before final user approval.

Mobile inspection caught the existing four-column Assessment table squeezing words into narrow vertical fragments. It now keeps readable column widths inside a keyboard-focusable horizontal-scroll container with a phone hint. Signals use compact separate reading items: status first, bold title, then supporting-source/strength references. Desktop uses two columns and phone uses one. Shared scoped styles apply to live and public output, with original text and destinations retained.

Repeated earlier runs were needed after the schema compatibility correction and the real mobile table defect; no gate was relaxed.
