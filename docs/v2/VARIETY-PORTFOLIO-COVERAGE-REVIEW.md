# Variety portfolio coverage: first review slice

The Hortifrut omission revealed a systematic gap between source names and the
catalog. The preceding Landscape checkpoint repairs published-summary discovery.
This independent catalog slice exposes primary-page names and the source backlog;
Landscape remains behind its blueberry review gate.

## What works

`/varieties/coverage` has a compact, filterable primary-source table. Expand a
source for every enumerated name, catalog/review links, codes, commercial names,
original URL and bounded scope. Unreadable means failed capture, never zero varieties.
The folded source plan retains all 77 supplied registry rows, including aliases and
multi-company rows. Berry hints and websites are research starting points.

The existing candidate builder/resolver feeds the existing identity queue. Search
covers codes/brands; source/company filters retain provenance. Two Florida Pearl
denominations remain separate. Ambiguous exact aliases and wrong-berry matches
require review. Rejected/distinct human decisions, literal notes and operator
knowledge survive replay. GET never writes inbox/canonical data or calls a provider.
Invalid observation files show a warning while existing source/inbox review stays
available. Authoring-only observations stay out of public/static pages. No canonical
Entity, Relationship, Evidence, Fact, schema or CPVO/footprint backend changes.

dates. The 90-day recheck flag is an operational default, not a completeness guarantee.

Names were manually enumerated from readable primary pages. The dated manifest in
`data/imports/variety-portfolio-observations-2026-10-07/` contains URLs, observed
codes/brands, page scope, limitations and unreviewed status; no article bodies.
This is a sampled reconciliation set, not an independently scored extraction
benchmark or live crawler. Future capture uses existing qualified acquisition and
human review. Company mention never proves breeding, rights or growing-region roles.
