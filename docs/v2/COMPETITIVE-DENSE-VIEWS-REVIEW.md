# Dense competitive research views

The initial sheet redesign covered the capability matrix but left People & Hiring as a timeline/list with raw record disclosures. Its filter form inherited an absolutely positioned matrix style. A shared archive panel also appended a second evaluation stylesheet after the page's layout stylesheet, restoring obsolete sidebar and positioning rules. Those were actual presentation defects; the earlier blanket readiness claim did not account for them.

The correction uses the existing green/sage OS palette, horizontal workspace tabs and full available content width. It removes the separate blue navigation rail. Compact headers lead with the current view and retained-record counts; narrative, raw observations and source history move behind each row's Inspect control. Desktop table actions use compact heights, while mobile retains larger touch targets. Source/claim distinctions and original research values remain unchanged.

People & Hiring now has one server-backed record sheet: person observations, employer/requisition/URL-grouped job histories, organizational observations and explicit non-hiring role context. Search covers names, company names/aliases, roles, skills, original observation fields and source identity. Filters cover record type, recorded role/function, observed status, source inspection and the organizational-change window. Column headings sort the complete filtered result before 50-row pagination. CSV export includes all matching rows, retained original fields and source references, with spreadsheet formula protection. People with the same name remain separate; job removal never implies a completed hire. Event, announcement and observation date bases remain explicit. Person references resolve only through exact same-batch IDs.

The same table component now covers entity profiles/gaps, directed relationships, company-specific exposure and mitigation, import batches/mapping reviews and saved comparisons. Each view has appropriate columns and a searchable/filterable/sortable full-result read model. Shared company/crop/destination scope remains, while view-specific table searches and sort keys reset when switching views. The capability matrix retains its original guarded assessment correction panel. Other record tables are read-only; saved comparisons remain frozen.

Captured coverage now uses a compact news table rather than tall article cards and an always-open filter form. It retains title/excerpt, publisher, true publication/capture/event dates, matched entities, inclusion reasons, tags/status and Reader/original-source actions. Full-archive text/publisher filters and title/publisher/publication sorting precede pagination and canonical deduplication is retained. Advanced company/berry/market/tag/date controls remain available. The shared component serves the existing competitor, entity, landscape, Explorer and linked-workspace panels; the duplicate stylesheet injection is removed there too. Main News/Reader workflows and underlying relevance/trust rules are preserved.

Source originals, mappings, ratings, analyst decisions and stored snapshots are not rewritten by this work. There is no new research acquisition, paid API, recurring monitor, publication decision or overall competitive score. The loopback preview uses the existing isolated `competitive-sheet-preview/inbox`, including its deliberate earlier test override, and keeps paid-provider keys/polling disabled.

Initial focused validation passes 59 tests; the final affected suite passes 88 tests in 35.47 seconds covering every evaluation view, private exports, before-pagination filtering, source/identity limits, retained job histories, explicit event dates and full-archive news selection. Actual desktop/mobile layout and workflow receipts, together with final current-head CI, are tracked in [draft PR #445](https://github.com/samsonFive/berry-intelligence-os/pull/445). The earlier [sheet receipt](COMPETITIVE-EVALUATION-SHEET-UI.md) is historical for the first matrix-focused pass. No merge or production deployment.
