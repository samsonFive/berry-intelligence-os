# Invariant matrix

Severity: **blocking** means publication/trust safety must fail closed;
**nonblocking** means an operational or audit-quality defect that must not
silently change trust state.

| Risk / invariant | Current protection | Current test | Missing protection | Required future test | Severity | Enforcement layer |
|---|---|---|---|---|---|---|
| Acquisition success auto-approves publication | Acquisition creates drafts/untrusted candidates; publish is a separate route | `test_review_publish_portability.py::test_publish_preserves_human_approval_and_trust_semantics` | No single end-to-end assertion over every acquisition adapter | Run each adapter success through intake and assert draft remains pending until explicit publish POST | Blocking | Acquisition service + workflow boundary |
| AI acts as reviewer | AI enrichment is `untrusted_suggestion`; form still requires reviewer | `test_publication_enrichment.py`; portability missing-reviewer assertion | No actor identity/permission distinction for automated callers | Submit AI actor/session to publish endpoint and assert 400/403 with no writes | Blocking | HTTP auth + publish service |
| Publication approval directly creates trusted Evidence | Publication-only path adds `pending_claim`; claim approval is separate | `test_trusted_evidence_semantics_repair_v1.py`; `test_atomic_evidence.py` | A publication with submitted facts creates Facts in same publish transaction; trust-tier semantics need explicit contract | Publish source with/without facts and assert exact trust tier, pending claim, and separate claim event | Blocking | Trust-tier service + publish service |
| Evidence proposals stay untrusted until separate human review | Atomic drafts require lineage/provenance; claim approve creates Fact separately | `test_atomic_evidence.py`; `test_trust_feedback.py` | No universal assertion that all proposal producers remain untrusted | Parameterize AI/media/registry proposal fixtures and assert no trusted feed eligibility pre-review | Blocking | Evidence repository + trust query |
| Malformed/provenance-incomplete draft cannot silently promote | Schema validation, required form fields, atomic parent/locator/provenance checks | `test_atomic_evidence.py`; portability missing reviewer | Publication route does not require all provenance fields checked by `check_eligibility` | Submit malformed source URL/identity/date and assert no Evidence, draft retained, actionable error | Blocking | Publish service |
| Repeated commands do not duplicate trusted publications | Deterministic id, duplicate conflict, idempotent review events | `test_review_publish_duplicate.py`; `test_review_events.py` | No process-level concurrency test | Replay identical publish concurrently and assert one Evidence, one event, stable draft outcome | Blocking | Repository/UoW + idempotency |
| Failure leaves no contradictory half-approved state | UoW rollback plus attachment/event compensation | `test_review_publish_portability.py`; duplicate tests | Audit append occurs inside UoW but filesystem atomicity is not transactional | Inject failure at each write boundary and assert all-or-nothing state and retryability | Blocking | UoW + durable event writer |
| Audit history is not silently overwritten | Event files use exclusive create; retries compare identity | `test_review_events.py::test_event_is_compact_append_only_and_idempotent` | No tamper/edit/delete detection or hash chain | Modify prior event, rerun append/verify, require explicit integrity failure | Blocking | Review-event ledger |
| Canonical/live records never mutate in validation | Existing tests use `tmp_path`; audit tooling can digest `data/`/`inbox/` | repository contract tests; Wave 2 gate | No repository-wide standard for mutation detection in this audit suite | Snapshot trusted/runtime trees before and after every validation command | Blocking | Gate harness |
| Double-click approval | Event idempotency and deterministic Evidence id | duplicate/review-event tests | Publish filesystem/entity race not exercised by two clients | Two simultaneous identical POSTs; assert one commit and idempotent second response | Blocking | UoW/repository |
| Retry after timeout | Duplicate publish path handles existing trusted id | duplicate tests | Timeout boundary between commit and response is not simulated | Commit then raise response timeout; retry and assert no duplicate/event | Blocking | Idempotency + API |
| Crash between writes | UoW and attachment restoration on exception | no direct crash injection | Crash points across draft delete, Evidence create, event append untested | Fault-injection matrix at every ordered write | Blocking | Transaction coordinator |
| Two concurrent reviewers | Exclusive event file creation helps event collision | no concurrent reviewer test | No expected-version guard on publication form/service | Two different decisions from same draft; assert one wins and other remains pending/conflict | Blocking | Publish service + repository lock |
| Stale browser state | Trusted identity conflict checks; trust feedback has stale versions | duplicate conflict; trust-feedback stale-version test | Publication draft has no submitted expected version | Add draft version and stale publish test, or document serialized single-writer guarantee | Blocking | Workflow/API |
| Wrong expected version | Trust feedback rejects stale versions | `test_trust_feedback.py::test_stale_version_and_superseded_undo_fail_without_new_events` | Publication review does not expose equivalent version check | Wrong-version publish must fail without event/data mutation | Blocking | Publish service |
| Missing actor | Publication form requires reviewer; claim routes require reviewer | portability missing-reviewer; atomic claim tests | Service-level `PublishRequest` accepts empty reviewer if called directly | Unit-test service rejects blank actor independently of HTTP | Blocking | Publish service |
| Automated/bot actor | AI provenance marked untrusted | publication enrichment tests | No actor allowlist or bot credential rejection | Use bot actor metadata and assert publish denied | Blocking | Auth/policy |
| Missing required reason | Reject route requires rejection reason; claim reject accepts reason | portability reject path | Publish has no reason requirement; policy is unclear | Decide and test whether publish rationale is required; reject empty reason if required | Nonblocking | Form/service policy |
| Invalid transition | Rejected drafts cannot publish; claim requires published source | portability rejected/missing tests; claim tests | No general transition table for every publication state | Table-driven invalid-state transitions with no side effects | Blocking | Domain state machine |
| Duplicate source URL | Duplicate identity currently uses deterministic id/identity fields | duplicate trusted identity tests | Same URL under different draft ids is not a stated duplicate rule | Same URL/different ids and same content/different URLs fixtures; assert policy outcome | Blocking | Duplicate detector |
| Same content, different URLs | No content hash identity in publication identity fields | none | Content equivalence policy absent | Canonical content hash fixture; assert dedupe or explicit allowed duplicate decision | Nonblocking | Duplicate detector |
| Superseded draft | Acquisition state tracks superseded signatures | `test_acquisition_state.py` | Publish path does not visibly reject a superseded draft | Supersede draft then publish; require block or explicit override event | Blocking | Acquisition state + publish |
| Body upgrade after metadata-only review | Portability carries article/transcript fields; source fidelity tests | `test_review_publish_portability.py`; source fidelity suite | No version binding between reviewed metadata and later body | Upgrade body after save, publish stale draft, require re-review or explicit diff | Blocking | Draft versioning |
| Transcript replacement | Atomic provenance requires locator/extraction provenance | `test_atomic_evidence.py` | No transcript content hash/version checked at claim approval | Replace transcript, approve old locator, require provenance mismatch block | Blocking | Transcript/evidence lineage |
| Corrupted draft | JSON loaders and schema validators fail/skip in bounded contexts | record validation; review missing-draft tests | Review queue behavior for malformed JSON is not characterized | Corrupt draft fixture; assert visible blocked/error state and no promotion | Blocking | Draft loader/review queue |
| Tampered provenance | Fields are carried and displayed; schema checks shape | atomic provenance tests | No cryptographic binding to source/transcript bytes | Alter provenance hash/locator after acquisition; require mismatch | Blocking | Provenance verifier |
| Publication succeeds, audit write fails | `remove_created_event` compensates event on later failure | no injected audit failure test | Filesystem event failure may occur after structured commit | Force event append failure and assert publication rollback or durable repair state | Blocking | Transaction coordinator |
| Audit succeeds, publication write fails | Exception handler removes newly-created event | review event compensation code | No injected publication failure after event creation | Force repository write failure after event append; assert event absent and draft retained | Blocking | Transaction coordinator |
| Evidence job starts early | Atomic review is separate route/workflow; static builder excludes inbox | `test_static_builder_has_no_review_event_dependency`; atomic tests | No queue/job gate keyed to publication review state | Start extraction job for pending publication and assert refusal/no trusted output | Blocking | Job scheduler |
| Static build reads partial record | Static builder reads trusted `data/` only | `test_build_static.py` | No atomic file-write/read consistency test | Replace record during build or inject partial JSON; build must fail closed, never publish partial HTML | Blocking | Static build + filesystem writes |
